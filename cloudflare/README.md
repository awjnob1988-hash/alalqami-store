# نشر إصلاح الطلبات والكوبونات — Worker 2.1

- شغّل `npm ci` ثم `npm test` و`npm run check:worker` و`npm run build`.
- طبّق `migrations/0001_checkout_recovery.sql` على قاعدة المتجر الموجودة **مرة واحدة فقط** قبل نشر Worker 2.1. يفحص المشغّل وجود `coupon_code_snapshot` قبل إعادة التنفيذ.
- انشر Worker مع الحفاظ على `ADMIN_PASSWORD` و`AUTH_KEY` وبقية الربوط الموجودة. لا تنسخ الأسرار إلى المستودع.
- رقم واتساب الافتراضي هو الرقم المنشور أصلًا في المتجر: `9647706050050`. يمكن تجاوزه بمتغير `SHOP_WHATSAPP`؛ القيمة غير الصالحة تمنع حفظ أي طلب جديد.
- تحفظ قاعدة البيانات أوقات الكوبونات بصيغة UTC، وتعرضها اللوحة وتستقبلها بتوقيت بغداد.
- `new` يعني **بانتظار تأكيد التاجر**. رابط واتساب يجهز الرسالة فقط؛ لا يوجد إشعار تسليم من واتساب في هذا التكامل. يغيّر التاجر الحالة إلى «مؤكد» بعد وصول الرسالة.
- الحذف النهائي للكوبون يزيله وسجلات استهلاكه ذريًا، ويحتفظ بمبالغ الطلبات ورمز الخصم في نسختها التاريخية.
- اختبارات الطلبات تستخدم D1 محلية فقط، ولا تنشئ طلبات أو رسائل واتساب حقيقية.

## تحديث 2.2: التوصيل والفواتير وحذف المنتجات

- طبّق `migrations/0002_delivery_fee.sql` مرة واحدة فقط. القيمة الافتراضية للطلبات القديمة صفر كي لا تتغير مبالغها بأثر رجعي.
- الطلب الجديد يحسب أجور توصيل ثابتة قدرها 6,000 دينار بعد خصومات المنتجات والكوبونات. لا تشمل الخصومات أجور التوصيل ولا يمكن تغييرها من بيانات المتصفح.
- `npm run build:invoice` يجمع مولد PDF وخط Amiri المرخص OFL في `invoice/invoice.bundle.txt`. ارفع هذا الملف كـText module مع `worker.mjs`، أو استخدم Wrangler الذي يتولى تحزيمه.
- تنزيل الفاتورة يجلب نسخة بيانات محمية بتسجيل الدخول؛ ينشئ المتصفح PDF مباشرة من تفاصيل الطلب المحفوظة. تبقى الفواتير صحيحة حتى بعد حذف منتج أو كوبون.
- فاتورة الطلب المكتمل تحمل حالة «مكتمل»؛ بقية الحالات تظهر كفاتورة مبدئية بحالتها الفعلية، ولا تفترض الفاتورة تحصيل الدفع.
- حذف المنتج نهائي ويتطلب تأكيدًا. يحافظ على نسخ المنتجات داخل الطلبات، ويزيل معرفه من نطاق كوبونات المنتجات؛ يوقف الكوبون إذا لم يبق أي منتج يشمله.
- عينات PDF للاختبار البصري فقط تحفظ في `tmp/pdfs/` ولا تنشر ضمن المتجر.

## تحديث 2.3: التقارير وأرشفة الفواتير

- طبق `migrations/0003_reports_and_invoice_archive.sql` مرة واحدة قبل تفعيل النسخة. الإضافة تحفظ الطلبات والمبالغ السابقة وتضيف فهارس للتاريخ والأرشفة.
- «التقارير والفواتير» يدعم اليوم والأسبوع (السبت إلى الجمعة) والشهر والسنة والفترات المخصصة، مع تجميع يومي/أسبوعي/شهري/سنوي وتقرير PDF عربي.
- الفترة تحدد حسب **تاريخ إنشاء الطلب بتوقيت بغداد**، مع شمول كامل يوم النهاية. أرقام التقرير تقرأ جميع طلبات الفترة عبر SQL، ولا تعتمد على آخر 100 طلب المعروضة في شاشة الطلبات.
- قيمة المبيعات تجمع `fulfilled` فقط، مع فصل صافي مبيعات المنتجات بعد الخصومات عن أجور التوصيل. هذا ليس حساب صافي الربح ولا سجلًا منفصلًا لتحصيل المدفوعات.
- «مرفوض» يحفظ داخليًا كـ`cancelled` و`cancel_reason=rejected` للمحافظة على قيود الجدول. الإلغاءات القديمة تبقى مصنفة «ملغاة» دون تخمين أنها رفض.
- ملفات PDF لا تخزن على الخادم. الأرشفة تخفي الفاتورة من القائمة النشطة ويمكن استعادتها؛ لا تحذف الطلب ولا تغير المبيعات أو استهلاك الكوبون. ملفات PDF التي سبق تنزيلها تبقى على جهاز المستخدم.
- قائمة فواتير الفترة مقسمة إلى صفحات (25 فاتورة)، وتظهر عناوين الأيام. نقاط التقارير والفواتير والأرشفة محمية بنفس تسجيل دخول الإدارة.
- `npm run build:admin` يزامن `reports-admin.js` مع HTML المضمن في Worker. شغله مع `build:invoice` قبل النشر؛ أو استخدم `npm test` و`npm run check:worker` اللذين يشغلانه تلقائيًا.
